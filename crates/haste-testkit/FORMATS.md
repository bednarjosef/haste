# Oracle data formats (oracles)

Everything the recorder mod and the dump scripts produce into `cache/oracle/26.3/`. All JSON is
UTF-8, versioned, written by Gson (mod) or serde (Rust). All dump files are re-generated by
`tools/recorder-mod/dump-server-oracles.sh`; the traces/screenshots/packets come from the client
recorder (Task 3).

Common conventions:
- Block coordinates for shape boxes are doubles in block space (block corner at the origin),
  rounded to 1e-6, `[minX, minY, minZ, maxX, maxY, maxZ]`.
- `"version"` is the format version, bumped on breaking change; loaders reject unknown versions.

## block_shapes.json

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "states": [
    {
      "id": 0,                      // global block state id (Block.BLOCK_STATE_REGISTRY id)
      "block": "minecraft:air",
      "properties": { "type": "bottom" },   // state properties, sorted by name; {} if none
      "collision": [[0.0,0.0,0.0,1.0,0.5,1.0]],  // boxes; [] = no collision
      "outline":   [[0.0,0.0,0.0,1.0,0.5,1.0]],  // visual selection outline boxes; [] = none
      "light": 0,                   // light emission 0..15
      "air": true,                  // isAir()
      "opaque": false,              // isSolidRender(): opaque full cube for light/render culling
      "fluid": "minecraft:water",   // only when the state has a fluid
      "fluid_empty": false,         // true when the fluid state is empty (block just *is* a fluid block)
      "neighbours": true            // only when set: shape may depend on neighbours (heuristic
                                    // flag, see tools/recorder-mod/NOTES.md; shapes recorded are
                                    // the no-neighbour shapes)
    }
  ]
}
```

35723 states in 26.3. `properties` names match `cache/datagen/26.3/reports/blocks.json`.

## entity_dimensions.json

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "types": [
    {
      "id": 1,                      // minecraft:entity_type registry protocol id
      "type": "minecraft:item",
      "width": 0.25,
      "height": 0.25,
      "eye_height": 0.2125,          // EntityDimensions.eyeHeight() (type default)
      "fixed": false                 // true = dimensions do not scale with pose (fixed())
    }
  ],
  "player": {                        // per-pose dimensions of a (server-side) player
    "standing":      { "width": 0.6, "height": 1.8,   "eye_height": 1.62 },
    "crouching":     { "width": 0.6, "height": 1.5,   "eye_height": 1.27 },
    "swimming":      { "width": 0.6, "height": 0.6,   "eye_height": 0.4 },
    // ... all 18 Pose values, keys are the serialized pose names
  }
}
```

## entity_models.json

Every model layer the client's `EntityModelSet` has baked (entity, armour and block-entity
models that are model layers), dumped by the recorder mod's `dump_models` scenario step.
In 26.3 signs and beds are NOT model layers (no `ModelLayers` entries; they render as baked
block models) and so do not appear here.

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "source": "client EntityModelSet (baked model layers)",
  "layers": [
    {
      "layer": "minecraft:pig#main",        // ModelLayerLocation: model id # layer name
      "texture_width": 64,
      "texture_height": 64,
      "parts": [                            // root part's children (root has no name)
        {
          "name": "head",
          "pivot": [0.0, 12.0, -6.0],       // PartPose x/y/z
          "rotation": [0.0, 0.0, 0.0],      // PartPose xRot/yRot/zRot, radians
          "scale": [1.0, 1.0, 1.0],         // PartPose xScale/yScale/zScale
          "cubes": [
            {
              "origin": [-4.0, -4.0, -8.0], // CubeDefinition origin (model units)
              "size": [8.0, 8.0, 8.0],       // CubeDefinition dimensions
              "uv": "0 0",                   // "u v" (duplicated numerically below)
              "u": 0.0, "v": 0.0,           // UVPair texCoord
              "mirror": false,
              "inflate": [0.0, 0.0, 0.0],    // CubeDeformation growX/Y/Z
              "visible_faces": ["down", "up", "north", "south", "west", "east"]
            }
          ],
          "children": [ /* more parts, same shape, recursive */ ]
        }
      ]
    }
  ]
}
```

## block_sounds.json

Every block's SoundType (the break/step/place/hit/fall sound events plus volume and pitch),
dumped by the recorder mod's `dump_block_sounds` scenario step. Vanilla keeps these as code
(BlockBehaviour's per-state sound type), not in the data generator's reports, so the recorder
reads them from the running game via `BlockState.getSoundType()`. Identical sound types are
deduped into a table referenced by index; a state is listed only where it differs from its
block's default (in 26.3 only the decorated pot's `cracked` variant does).

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "source": "client block registry (BlockState.getSoundType)",
  "sound_types": [                        // dedupe table, referenced by index
    {
      "break": "block.stone.break",       // sound event ids; vanilla's "no sound" is
      "step": "block.stone.step",         //   "minecraft:intentionally_empty"
      "place": "block.stone.place",
      "hit": "block.stone.hit",
      "fall": "block.stone.fall",
      "volume": 1.0,                      // SoundType volume/pitch multipliers
      "pitch": 1.0
    }
  ],
  "blocks": {
    "minecraft:stone": { "sound": 0 },    // default sound type index for every state
    "minecraft:decorated_pot": {
      "sound": 42,
      "states": [                         // only states differing from the default
        { "properties": { "cracked": true }, "sound": 43 }
      ]
    }
  }
}
```

## block_properties.json

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "blocks": {
    "minecraft:stone":   { "friction": 0.6,  "speed_factor": 1.0, "jump_factor": 1.0 },
    "minecraft:ice":      { "friction": 0.98, "speed_factor": 1.0, "jump_factor": 1.0 },
    "minecraft:slime_block": { "friction": 0.8, "speed_factor": 1.0, "jump_factor": 1.0 },
    "minecraft:blue_ice": { "friction": 0.989, "speed_factor": 1.0, "jump_factor": 1.0 }
  }
}
```

`friction` is the block's slipperiness; `speed_factor`/`jump_factor` are multipliers applied while
the entity is standing on the block. Defaults for blocks not overriding: 0.6 / 1.0 / 1.0.

## block_entity_types.json

Which block carries which `minecraft:block_entity_type` (the block side of vanilla
`BlockEntityTypes`' valid-block sets). `blocks` is the authoritative view the client loads: for
every block state where `BlockState.hasBlockEntity()` is true, the type `EntityBlock
.newBlockEntity(BlockPos.ZERO, state)` returned — the same call `LevelChunk.setBlockState` makes
when a block update places the block, so the client can create the entity itself (the server
sends no `block_entity_data` for a plain placement). `types` is the registry's own view, for
comparison. States of one block share the type; a block whose states disagree (or return no
entity for some of them) is emitted per state under `states` instead — none in vanilla 26.3.

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "types": [
    {
      "id": 0,                            // registry id (BuiltInRegistries.BLOCK_ENTITY_TYPE)
      "type": "minecraft:furnace",
      "valid_blocks": ["minecraft:furnace"]
    }
  ],
  "blocks": {
    "minecraft:chest": "minecraft:chest",
    "minecraft:spawner": "minecraft:mob_spawner",
    "minecraft:oak_sign": "minecraft:sign"
  },
  "states": { }                          // state id -> type, only for blocks in `states`
}
```

## traces/<name>.json

Physics traces recorded from the vanilla client (Task 3). One file per scripted input sequence.

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "name": "walk-10s",
  "world": { "seed": 12345, "spawn": [0.5, -60.0, 0.5], "dimension": "minecraft:overworld" },
  "player": { "yaw": 0.0, "pitch": 0.0, "initial_pos": [8.5, -60.0, 8.5] },
  "ticks": [
    {
      "tick": 0,
      "input": { "forward": 1.0, "strafe": 0.0, "jump": false, "sneak": false, "sprint": false },
      "pos": [8.5, -60.0, 8.5],
      "velocity": [0.0, 0.0, 0.0],
      "on_ground": true,
      "pose": "standing",
      "dimensions": [0.6, 1.8]
    }
  ]
}
```

Positions/velocities are doubles `[x, y, z]`. `forward`/`strafe` are the impulse values the client
applied that tick (1.0 forward, -1.0 back, ...). `pose` is the serialized pose name; `dimensions`
are `[width, height]` at that tick (changes with pose).

## packets/<name>.bin

Length-prefixed clientbound play packets as recorded by the proxy, decompressed:

```
header:
  u8[5]   "HSTK\0" magic
  u32     protocol version (777 for 26.3)
  u64     unix millis timestamp
  u32     packet count
then per packet:
  u32     length N (uncompressed clientbound frame length, excluding this field)
  u8[N]   the decompressed packet body (first varint is the packet id, as on the wire)
```

Multi-byte integers are big-endian, matching the protocol itself.

## block_classes.json

For every block id, the simple names of its Java class and superclasses up to `Block`
(exclusive of `BlockBehaviour`). Which face-skip rule (`BlockBehaviour.skipRendering`) a block
uses is a property of its class, so the mesher maps class names to culling rules from this dump
instead of a hand-written block list (mods add blocks). Dumped by the recorder mod's
`BlockClassDump` (called from `ServerDumps.dumpAll`).

```jsonc
{
  "version": 1,
  "minecraft": "26.3",
  "blocks": {
    "minecraft:glass":  ["GlassBlock", "TransparentBlock", "HalfTransparentBlock", "Block"],
    "minecraft:iron_bars": ["IronBarsBlock", "CrossCollisionBlock", "Block"]
    // ... every registered block, [] never occurs (every block extends at least Block)
  }
}
```

Blocks absent from the dump use the default rule (no skip); the loader never panics on unknown
ids.

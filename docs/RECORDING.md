# Recording oracle data from the real client (WS8)

The server-side dumps (block shapes, entity dimensions, block properties) need no display and
are regenerated by anyone with:

```
tools/recorder-mod/dump-server-oracles.sh
```

Everything on this page needs the real vanilla **client** and a display, so they are **the
user's part**: physics traces, screenshots and benchmarks. This page is exactly what to run.

## 0. One-time setup

```
# from the repo root (a worktree works the same)
tools/recorder-mod/build.sh
```

This builds `tools/recorder-mod/build/haste-recorder.jar` (javac against the client + server
jars in `cache/`, Fabric Loader, sponge-mixin and the Fabric API modules it needs; no Gradle).

The client must run with Fabric Loader. Until WS7's launcher exists, start the vanilla client
through Fabric manually:

```
cd <an empty dir you own>            # client working dir; the cache is found via ../cache
mkdir -p mods
cp <repo>/tools/recorder-mod/build/haste-recorder.jar mods/
cp <repo>/cache/server-spike/mods/fabric-api-*.jar mods/

# fabric-client-launch style (Fabric's launcher jar in the versions dir) — adjust paths:
java -jar fabric-client-launch.jar --accessToken 0 --userProperties {} --gameDir . \
     --assetsDir <repo>/cache/assets
```

Practical shortcut while WS7's `haste setup` is pending: use any existing Fabric installation
of 26.3 (e.g. from the Fabric installer with "client" for release 26.3), drop the two jars
above into its `mods/`, and start it the way you usually start that installation.

**Where files land**: `../cache/oracle/26.3/` relative to the client's game directory. The
recorder falls back to `oracle/26.3` inside the game dir if no `../cache` exists. If your
client runs from somewhere else, set the working directory so `../cache` resolves to the repo's
`cache/` (or symlink it).

## 1. The recording world

One fixed world for everything, so traces and screenshots are comparable across clients:

- **Superflat, seed `0`**, one layer of `minecraft:stone` (classic preset), overworld.
- Create it once in singleplayer ("Create New World" → More → World Type: Superflat →
  presets: Classic Flat), name it `haste-recording`, set the seed to `0` in More options.
- Creative mode, but for traces switch to **Survival** (creative flight would change physics).
- TP to a flat, clear spot (at least 30 blocks of open flat stone):
  `/tp 8 -60 8` then `/setblock 8 -59 8 air` if anything is in the way.

Terrain the scripted sequences expect (build once, ~2 minutes with commands; standing at the
TP spot, facing **north = -Z**):

```
# wall for walk-into-wall: 3 blocks ahead
/fill 8 -60 3 8 -57 5 minecraft:stone

# slab for step-up-slab: bottom slab 8 blocks ahead, with a stone block after it
/fill 8 -60 0 8 -60 0 minecraft:oak_slab[type=bottom]

# water for swim: a 2-deep trench from 15 blocks ahead
/fill 8 -60 15 8 -59 25 minecraft:water

# fall: a 20-high pillar 10 blocks to the side, climb it (fly), then fall straight
# (sequence runs with no keys held; stand on top before starting it — see "run order" below)
```

Coordinates assume the player stands at (8.5, -60.0, 8.5) facing north. North-facing matters:
the scripted input is "forward" only, so sequences run straight ahead in the direction you
face when the recording starts.

## 2. Physics traces

In the world (Survival, standing at the start spot, facing north):

```
/haste record baseline
```

Then **do not touch keyboard or mouse** for ~50 s (10 sequences x 100 ticks + overhead). The
chat announces each file as it finishes; `/haste stop` aborts cleanly. Output:

```
../cache/oracle/26.3/traces/baseline-walk.json
../cache/oracle/26.3/traces/baseline-sprint.json
... (jump, sprint-jump, stop, sneak, walk-into-wall, step-up-slab, swim, fall)
```

**Run order for the terrain-dependent ones**: the sequences run back-to-back from wherever the
previous one left the player. The world layout above is spaced so that running all ten from
(8.5, -60, 8.5) works: wall at 5 blocks (hit during walk-into-wall), slab at 8 (stepped on),
water at 15-25 (swim), then fall teleports nothing — **for `fall` the player must already be
somewhere high**: record the first nine sequences, then fly up 20 blocks, hover, and run
`/haste record baseline-fall2` and delete the nine duplicates it re-records (or just accept
the fall trace from the second run by naming it `baseline-fall` by hand). The fall sequence
holds no keys, so gravity does the work.

**Verify** (back in the repo):

```
cargo test -p haste-testkit traces        # format round trip
python3 tools/recorder-mod/validate-traces.py   # checks: walk moved ~blocks, jump left ground, ...
```

## 3. Screenshots

Fixed camera positions in the same world. Stand somewhere with a clear view, look in a fixed
direction, then:

```
/haste screenshot flat-noon-1
```

One PNG + one JSON per shot (`screenshots/<name>.png` + `.json`): the HUD is hidden
automatically during capture. Keep F3 closed (the debug overlay is not hidden by the capture).
Record the camera once per scene, e.g.:

| name          | position          | yaw | pitch | time |
|---------------|-------------------|-----|-------|------|
| `flat-north`  | 8.5, -60, 8.5     | 180 | 10    | noon (6000) |
| `flat-dawn`   | 8.5, -60, 8.5     | 180 | 10    | dawn (/time set 23000) |
| `stone-close` | 0.5, -59, 0.5     | 45  | 0     | noon |

The camera JSON records what was actually used (pos, yaw, pitch, fov, time of day, render
distance) — reproducing it in Haste is WS3's camera setup.

## 4. Benchmarks

```
/haste bench vanilla
```

Records 60 s of frame times + RSS (`/proc/self/status` VmRSS) to `bench/vanilla.jsonl` while
you fly the fixed route: from (8.5, -60, 8.5) face north, hold W + fly straight at eye height
for ~15 s, turn right (east) 15 s, right again (south) 15 s, right again (west) 15 s — a slow
square, ~constant chunk throughput. For "vanilla + Sodium" numbers, install Sodium in a
second Fabric profile with the same world and run `/haste bench vanilla-sodium` there.

Summary table (from the repo):

```
cargo run -p haste-testkit --example bench-report -- ../cache/oracle/26.3/bench
```

or read the JSONL with `haste_testkit::bench::Bench::load`.

## 5. Packet recordings

For wire fixtures (WS1/WS2), run the local offline server and join through the proxy from
the vanilla client (see `cache/server-spike` + the spike's `scripts/server.sh`):

```
# terminal 1: the server
cd cache/server-spike && bash ../server-spike-scripts-server.sh   # or the spike repo's server.sh

# terminal 2: the proxy (from the repo)
cargo run -p haste-testkit --bin haste-packet-proxy -- \
    --listen 127.0.0.1:25566 --server 127.0.0.1:25565 --name world-load

# terminal 3: the client connects to 127.0.0.1:25566 instead of 25565
```

Walk around, open a chest, break blocks; disconnect to stop. Output:
`cache/oracle/26.3/packets/world-load.bin` — every clientbound play packet, decompressed,
length-prefixed (format in `crates/haste-testkit/FORMATS.md`).

## What to check afterwards

```
ls -la cache/oracle/26.3/traces cache/oracle/26.3/screenshots cache/oracle/26.3/bench
python3 tools/recorder-mod/validate-dumps.py          # server dumps unchanged
cargo test -p haste-testkit                           # loaders accept the new files
```

If anything looks wrong, the log (`logs/latest.log` in the game dir) has `haste-recorder`
lines for every write.

# GUI, so its origin is (152, 52) and a slot's centre is its menu position + 8 (vanilla
# EnchantmentMenu: item (15,47), lapis (35,47); the player inventory and hotbar are the
# container screen's standard rows).
#   item (menu slot 0)   -> (152+15+8, 52+47+8) = (175, 107)
#   lapis (menu slot 1)  -> (152+35+8, 52+47+8) = (195, 107)
#   player inventory (slots 2+) -> (152+8+8, 52+84+8) = (168, 144), step 18
#   hotbar (slots 29+)   -> (152+8+8, 52+142+8) = (168, 202), step 18
# The three enchant rows are not slots: EnchantmentScreen.mouseClicked treats a click in
# x [60,168) y [14+19*i, 14+19*i+19) (menu coordinates) as row i's button; row 1 in GUI
# coordinates is x [212,320), y [66,85), so its centre (266, 75) clicks it.
# The runner tps us into the check's own area, gives a wooden sword, lapis and the levels
# and places the table when the setup screenshot appears. With no bookshelves around, row
# 1's cost is 1-2 levels and it always costs 1 lapis (vanilla EnchantmentMenu.clickMenuButton:
# enchantmentCost = buttonId + 1).
